# Spectra 1.0 — QA report (17 November 2026)

All tests are automated, and none of the content-administration code changes the base content: with no pack published, the 283-screen parity remains at 0 differences. All tests are automated (Playwright, Chromium 153) and were run on the exact files in this zip.

| Suite | What it checks | Result |
|---|---|---|
| **Content parity** — 6 loading methods | Every view, both chart versions, every organism and every drug (283 screens). Compared word for word against the original design running the same data, so the redesign adds or changes no clinical wording. Methods: `file://` split · `file://` standalone · HTTP split · HTTP standalone · strict-CSP · inside an iframe. | **0 differences** in all 6 |
| **Content audit** | Keyed comparison with the verified 4 Oct 2026 content, after the 17 Nov update and the 18 Nov source re-audit | Only the intended screens changed: 33 changed, 3 added, 0 removed (see VERIFICATION-LOG) |
| **Data integrity** | Organism IDs, 212 citation keys → 63 references, HTTPS links, duplicates, "undefined"/NaN | 0 problems |
| **Devices** (touch emulation where relevant) | iPhone SE (320), iPhone 15 Pro, Pixel 7, Galaxy S9+, Galaxy Z Fold folded (280), iPad Mini, iPad Pro 11 landscape, desktop 1366 and 1920 | **All pass** |
| — per device | No sideways scroll on any tab; every tap target hit-tested (not covered by bars); fingerprint has one square per organism, ≥24 px targets, legend present; popover opens with the correct organism, stays on-screen and closes; **Show on this page** scrolls to and highlights the matching card; keyboard (arrows / Enter / Esc) on desktop; usage panel fits the screen and closes with Esc | pass |
| **Analytics** | `session_start`, `screen_view` (tap and search paths, dwell), `search_select` (query, rank), `search_no_result` (**query text not stored**, length only), `fingerprint_tap`; schema fields, module/content version on every event; CSV export row count and BOM | pass |
| **Host bridges** | iframe: `ready` message, events to parent, `setUser` (uid/role/app version applied to later events), `getSummary` reply | pass |
| **Endpoint** | Batched POST with `Authorization` header, CORS pre-flight, every generated event received (7/7), outbox emptied | pass |
| **Storage blocked** | localStorage and sessionStorage throwing (private mode / locked-down WebView): app works, theme switch works, events kept in memory | pass |
| **Errors / security** | No JavaScript errors or console errors; no CSP violations under strict CSP; HTML-injection text in search is escaped; CSV cells starting with = + - @ are neutralised | pass |
| **Content administration** (end to end, with a test server enforcing the sysadmin token) | Users: no editor button, a non-sysadmin grant refused, programmatic edits refused; an iframe grant refused when `parentOrigin` is `*`. Admin: edit coverage; refuse a save without a reason (typed input kept); refuse an unknown reference key and a duplicate drug name; rename a drug (pharmacist notes follow); add a reference, a new antiviral and a new antifungal organism; edit a hard-coded organism name; remove a drug (two-tap); live preview on the admin's device; HTML-injection drug name escaped. Publish v1 accepted by the server; publish with a wrong token **refused (401)**. An ordinary user then receives v1 from the server: all edits visible, "Local update" rows in What changed, new reference listed, 2019 archive unchanged, `content_loaded` logged, content version `…|pack-v1`. The same pack works as bundled `content-pack.js`. Undo from History published as v2 and restores the drug. Admin console fits a 320 px phone. | **All pass** |
| **Reference server** (`examples/endpoint-receiver.js`) | no session → 401 · ordinary user → 403 · sysadmin → 200 · replayed version → 409 · attempt to remove published history → 400 | pass |
| **Screens** | Light, dark and system themes; reduced motion respected | pass |

**Not covered by this environment:** the Firefox (Gecko) and Safari (WebKit) engines were not installed here. Device tests emulate iOS and Android on Chromium. The code uses only widely supported features with fallbacks (no `eval`, every storage call guarded, colour fallbacks for `color-mix`). A short smoke test on a real iPhone (Safari/WKWebView) and an Android WebView before go-live is still recommended.
